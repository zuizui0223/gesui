# 原本EEA監視局×HydroBASINS H7からのH6内追加流域の実在性監査（source-only）

**凍結日：2026-11-15。既存PR #103のsource-only STOP後の事後探索。原本の生物応答は見ずに、追加データが本当に存在するかを評価する。**

## 問いと厳密な目標

前段の219 H7（二期間とも植物EIV品質を満たす）・86真正H6のうち、H6内に最低2つの異なるH7を持つのは**30 H6**。前段で固定した基準は「異なるH7≥100・H6≥40・国≥5」であり、**30→40 H6に必要なのは、最低10の異なる単一H7親H6で2つ目のH7が増えること**。基準は緩めない。

### Source frame A: 原本2018/2022 EEA監視記録だけで二期間H7を増やせるか

- 元の真正EEA18/22+EPA1819監視局割当6,330件（GitHub Actions #43165326244）を SHA256 `a396eaed1c0b406eb3bbb7178e04ba91989ab5964c4f0175fc1193673d624d89` で検証。各記録のH7、panel、期間、国の**元メタデータのみ**を使用。EQR数値、栄養濃度、植物・蝶応答を開かない。
- 元の454 H7×期間、232 H7/90 H6（SHA256 `1296d1ded7f1ee185854cad6d1ece1dbb1f94b4e2f48856c8c487a3f3d002fca`）のH7 IDと期間だけを照合。
- EEA18に対応する2017–2019期とEEA22に対応する2020–2022期の**両方**に真正現地監視があるH7集合を導出。各期を同じH7の2独立地理反復にはしない。
- この元EEA frameだけの追加可能H7の数を出す。新規H7のH6親IDをまだ分からない場合も、「親H6の改善数≤追加可能なユニークH7数」という**厳密な上限**を示す。最低10 H6を増やせないことが分かれば、元frameの二期間サンプル追加は source-only 不成立とする。
- 1期だけのEEA監視H7は別集計するが、**両期データが存在するH7とは交換しない**。欠測の期を「生物不在」「水質ゼロ」としない。

### Source frame B: 単一EEA期または別のGBIF原本H7を使う新規コホート

もしAの厳密上限が不足なら、次に計画できるのは**別コホート**であり、前段の454行に無断で追加しない。

- 出発点は元のHydroBASINS H7 Level7、EEA18またはEEA22のどちらかに対応するH7（さらに元1219 H7 indexに存在するH7）。源の国、監視局訪問の有無、元の流域面積、上流面積などだけを扱う。
- 真正Level7→Level6の親割当は公式HydroBASINS多角形の95%以上重複で確認。PFAF文字列の先頭、近所、H3の代理親IDの使用禁止。
- 元の植物/蝶GBIF 2017–2019/2020–2022両期のspeciesKey機会、独立H6の追加機会、EIV得点率等を**生物効果を見る前**に確認する。元のsourceだけで未取得なGBIF種出現は未知であり、0とはしない。
- 新規EEA局が1期のみなら、元の同一局・同一評価法EQR二期間と**同等でない**。水域EQRとの連鎖はさらに別設計・同一測定局条件が必要。
- 元frameに存在する単期EEA H7の数が多くても、それが「追加H6に≥2種得点H7を確保した」ことにはならない。GBIF原本源（taxa+記録数・付随努力）取得、原本分類品質、受理数値EIVの対応率≥40%、既知HNS源スコア率をすべて前結果なしで評価してから新コホートを開く。

### 判定

- **A上限 ＜10ユニーク新H7：** 元EEA両期を保持したまま≥40 H6に到達することは数学的に不可能（追加H7一つが既存単一H7親H6を改善できる数は最大1）。
- **B：** 対象候補数と元source overlapのみ、効果・NUTRI・HNSは推定せず次の真正分類・原本コホートを設計する。新しくsource cohortを増やすときは新しい検証であり元の30/40 source STOPを再分類してはいけない。
- 研究倫理：資料は公開原本とそのSHAに限定、EIVの未承認再配布なし。main/chocho/親PR #103を変更しない。先行肯定・否定・STOPを保存。
