### 統合時の共通規則

1. **出所の重複**：PRではなく、元調査・施設・観測局・地点年・個体／区画をキーにする。既存の欧州454/451/426/139行は、解析適格条件で変わる同系列の標本である。分母の違いだけを独立再現の根拠にしない。

3. **部分経路の統合**：原観測が対応する範囲で階層モデル、処理対照と応答が揃う範囲で経路別メタ解析を行う。対応していない辺の係数積は算出しない。
4. **反証の保持**：国外転送、時間差、属内分解、前年記録調整、下流負の対照を主結果の付随情報として保持する。都合のよいモデルだけを選んで代表効果にしない。

### 同じ鎖へ接続するために残るもの

この系列には**同じ湿地で水質と植物を測る**強みがあるが、下水の到達、河川から河岸への移行、植物の栄養品質、現地植食者の測定が揃わない。Shannonは群集多様性であり、食草現存量・葉N/P・植食者が利用できる資源量ではない。よってフランスのTP→植物NUTRIの辺へ、同じ係数として投入しない。

水質と植物の関連、登録点近接と植物の関連、歴史的監視記録付き近接と植物の関連は別の推定対象である。肯定的な+0.18062だけを代表値とせず、重み・源種別・年度・標本の変更を伴う感度を一つの系列として報告する。州の留保や再計算成功を、新たな独立研究数へ変換しない。

源監査の数字も一列の単調な絞り込みとは限らない。#50と#54はTN/TP特徴地点34/83/31を報告し、#53は35/93/32を報告する。各プロトコル・実装に由来する差を完全に照合する前に、これらを統一した曝露台帳や独立源数へ合算しない。#53の「近接26→同地域対照付き21」は同一報告内の条件差として確認できるが、#50の失敗条件を後から達成したことを意味しない。

### コード監査による重要な訂正：#53と#54の数値報告は同じ採用条件ではない

2026年11月20日に各固定コミットの原抽出コードを取得して比較した。[#53コード](https://github.com/zuizui0223/gesui/blob/73882cd996ca81a35b7aaebec8c60239492c85f9/scripts/gesui_NWCA2021_ECHO_FY2021_FY2022_DMR_exact_NP_source_chuncks.py) は `MONITORING_LOCATION_CODE` を読まず、EXO特徴地点内の採水位置を区別していない。またNODIは空欄または`0`、数値修飾は空欄・`=`・`E`を許容する。コメントの「estimatedを認めない」と実際の条件が一致しない。

既存の公開集計JSONをpermit＋featureのハッシュで照合すると、#53のTN35／TP93／両方32に対し、#54側は34／83／31を再現した。TNで1、TPで10特徴地点が#53のみ、逆方向の差は0だった。[比較記録](evidence/NWCA_DMR_RECEIPT_COMPARISON_20261120.json)。ただし、集計表だけでは各差分を採水位置・E・NODIのどれに帰属できるか判別できず、件数差の全原因を確定したとはしない。全国DMRの再読・植物係数の再推定は未実施。

**コード監査時点では75湿地・177湿地の両方を保留し、その後、下記の地点ID照合で75湿地の標本同一性を確認した。177湿地の厳格条件への転用は保留のままである。** 元報告の「実測」という表現には、この採水位置・推定値条件の限定を付す。源件数の一致だけで植物係数の再現を主張せず、地点所属・共変量・応答の同一性を別に判定する。
